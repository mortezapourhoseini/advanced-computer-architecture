## ۱. کد مثال

کتاب CAQA و اسلاید درس این کد را اجرا می‌کنند (کتاب جابه‌جایی‌های ۳۲ و ۴۴ و اسلاید ۳۴ و ۴۵ دارد، فرقی نمی‌کند):

```asm
1. L.D     F6,32(R2)
2. L.D     F2,44(R3)
3. MUL.D   F0,F2,F4
4. SUB.D   F8,F2,F6
5. DIV.D   F10,F0,F6
6. ADD.D   F6,F8,F2
```

پیکربندی: ۳ ایستگاه رزرو برای جمع‌کننده (Add1 تا Add3)، ۲ ایستگاه برای ضرب‌کننده (Mult1 و Mult2) که ضرب و تقسیم را انجام می‌دهد، و بافرهای بارگذاری Load1 و Load2 و غیره.

یک جدول **وضعیت دستور** هم نشان می‌دهیم. کتاب تأکید می‌کند که این جدول **بخشی از سخت‌افزار نیست** و فقط برای فهم ماست. وضعیت هر دستور در ایستگاه رزروش نگه‌داری می‌شود.

## ۲. عکس اول: فقط اولین بارگذاری تمام شده

همه‌ی دستورات صادر شده‌اند، ولی فقط اولین `L.D` نتیجه‌اش را نوشته است. دومین `L.D` آدرسش را حساب کرده و منتظر حافظه است.

**وضعیت دستورات:**

| دستور | صدور | اجرا | نوشتن نتیجه |
|---|---|---|---|
| دستور `L.D F6,32(R2)` | انجام شد | انجام شد | انجام شد |
| دستور `L.D F2,44(R3)` | انجام شد | انجام شد | |
| دستور `MUL.D F0,F2,F4` | انجام شد | | |
| دستور `SUB.D F8,F2,F6` | انجام شد | | |
| دستور `DIV.D F10,F0,F6` | انجام شد | | |
| دستور `ADD.D F6,F8,F2` | انجام شد | | |

**ایستگاه‌های رزرو:**

| نام | Busy | Op | Vj | Vk | Qj | Qk | A |
|---|---|---|---|---|---|---|---|
| ایستگاه Load1 | No | | | | | | |
| ایستگاه Load2 | Yes | Load | | | | | 44 + Regs[R3] |
| ایستگاه Add1 | Yes | SUB | | Mem[32 + Regs[R2]] | Load2 | | |
| ایستگاه Add2 | Yes | ADD | | | Add1 | Load2 | |
| ایستگاه Add3 | No | | | | | | |
| ایستگاه Mult1 | Yes | MUL | | Regs[F4] | Load2 | | |
| ایستگاه Mult2 | Yes | DIV | | Mem[32 + Regs[R2]] | Mult1 | | |

**وضعیت ثبات‌ها:**

| فیلد | F0 | F2 | F4 | F6 | F8 | F10 |
|---|---|---|---|---|---|---|
| مقدار Qi | Mult1 | Load2 | | Add2 | Add1 | Mult2 |

خواندن این جدول‌ها:

- **دستور `SUB.D` در Add1:** عملوند اول (F2) هنوز آماده نیست و منتظر Load2 است (Qj). عملوند دوم (F6) آماده بود، چون اولین بارگذاری تمام شده، پس **مقدارش** در Vk است.
- **دستور `ADD.D` در Add2:** هر دو عملوند منتظرند: F8 از Add1 و F2 از Load2.
- **ثبات F6:** فیلد Qi آن Add2 است، نه Load1. یعنی آخرین نویسنده‌ی F6 دستور `ADD.D` است. نتیجه‌ی بارگذاری اول قبلاً نوشته شده و هر کس آن را لازم داشته، مقدار را گرفته است.

## ۳. حذف WAR بین DIV.D و ADD.D

بین `DIV.D` (که F6 را می‌خواند) و `ADD.D` (که F6 را می‌نویسد) ضدوابستگی هست. در جدول امتیاز، `ADD.D` باید در نوشتن نتیجه صبر می‌کرد تا `DIV.D` عملوندش را بخواند. اینجا **هیچ صبری لازم نیست**. دو حالت:

- **اگر بارگذاری F6 تمام شده باشد** (حالت نشان‌داده‌شده): مقدار F6 در Vk ایستگاه Mult2 کپی شده است. پس `DIV.D` دیگر به ثبات F6 کاری ندارد و `ADD.D` می‌تواند هر وقت خواست F6 را بنویسد.
- **اگر بارگذاری تمام نشده بود:** فیلد Qk ایستگاه Mult2 به Load1 اشاره می‌کرد. باز هم `DIV.D` به **ایستگاه** Load1 وابسته است، نه به ثبات F6. نوشتن `ADD.D` در F6 روی آن اثری ندارد.

کتاب می‌گوید این دو مزیت بزرگ روش توماسولوست: **توزیع منطق تشخیص مخاطره** (چند دستور منتظر یک نتیجه همزمان با پخش CDB آزاد می‌شوند) و **حذف توقف برای WAR و WAW**.

## ۴. عکس دوم: ضرب آماده‌ی نوشتن است

تأخیرهای کتاب برای این مثال‌ها: بارگذاری ۱ سیکل، جمع ۲ سیکل، ضرب ۶ سیکل و تقسیم ۱۲ سیکل. وضعیت وقتی `MUL.D` آماده‌ی نوشتن نتیجه است:

| دستور | صدور | اجرا | نوشتن نتیجه |
|---|---|---|---|
| دستور `L.D F6,32(R2)` | انجام شد | انجام شد | انجام شد |
| دستور `L.D F2,44(R3)` | انجام شد | انجام شد | انجام شد |
| دستور `MUL.D F0,F2,F4` | انجام شد | انجام شد | |
| دستور `SUB.D F8,F2,F6` | انجام شد | انجام شد | انجام شد |
| دستور `DIV.D F10,F0,F6` | انجام شد | | |
| دستور `ADD.D F6,F8,F2` | انجام شد | انجام شد | انجام شد |

| نام | Busy | Op | Vj | Vk | Qj | Qk |
|---|---|---|---|---|---|---|
| ایستگاه Mult1 | Yes | MUL | Mem[44 + Regs[R3]] | Regs[F4] | | |
| ایستگاه Mult2 | Yes | DIV | | Mem[32 + Regs[R2]] | Mult1 | |

بقیه‌ی ایستگاه‌ها آزادند. در وضعیت ثبات‌ها فقط F0 (منتظر Mult1) و F10 (منتظر Mult2) باقی مانده‌اند.

نکته‌ی کلیدی: `ADD.D` **قبل از** `DIV.D` (که اولش است) تمام شده و F6 را نوشته است. WAR حذف شد، چون `DIV.D` مقدار قدیمی F6 را قبلاً کپی کرده بود. همچنین کتاب می‌گوید حتی اگر بارگذاری F6 تأخیر داشت، جمع می‌توانست بدون مخاطره‌ی WAW در F6 بنویسد.

## ۵. الگوریتم دقیق

شکل ۳.۹ کتاب شرط‌ها و کارهای هر مرحله را دقیق می‌گوید. در شبه‌کد زیر rd مقصد، rs و rt منبع‌ها، imm عدد ثابت، r ایستگاه یا بافر تخصیص‌یافته، RS ساختار ایستگاه‌ها، RegisterStat وضعیت ثبات‌ها و Regs فایل ثبات است:

```text
Issue, FP operation        wait until: station r is empty
    if (RegisterStat[rs].Qi != 0) RS[r].Qj = RegisterStat[rs].Qi
    else { RS[r].Vj = Regs[rs]; RS[r].Qj = 0 }
    if (RegisterStat[rt].Qi != 0) RS[r].Qk = RegisterStat[rt].Qi
    else { RS[r].Vk = Regs[rt]; RS[r].Qk = 0 }
    RS[r].Busy = yes; RegisterStat[rd].Qi = r

Issue, load or store       wait until: buffer r is empty
    if (RegisterStat[rs].Qi != 0) RS[r].Qj = RegisterStat[rs].Qi
    else { RS[r].Vj = Regs[rs]; RS[r].Qj = 0 }
    RS[r].A = imm; RS[r].Busy = yes
    load only:  RegisterStat[rt].Qi = r
    store only: if (RegisterStat[rt].Qi != 0) RS[r].Qk = RegisterStat[rt].Qi
                else { RS[r].Vk = Regs[rt]; RS[r].Qk = 0 }

Execute, FP operation      wait until: RS[r].Qj == 0 and RS[r].Qk == 0
    compute result with Vj and Vk

Execute, load/store step 1 wait until: RS[r].Qj == 0 and r is head of load-store queue
    RS[r].A = RS[r].Vj + RS[r].A
Execute, load step 2       wait until: load step 1 complete
    read Mem[RS[r].A]

Write result, FP or load   wait until: execution complete at r and CDB available
    for all x: if (RegisterStat[x].Qi == r) { Regs[x] = result; RegisterStat[x].Qi = 0 }
    for all x: if (RS[x].Qj == r) { RS[x].Vj = result; RS[x].Qj = 0 }
    for all x: if (RS[x].Qk == r) { RS[x].Vk = result; RS[x].Qk = 0 }
    RS[r].Busy = no

Write result, store        wait until: execution complete at r and RS[r].Qk == 0
    Mem[RS[r].A] = RS[r].Vk; RS[r].Busy = no
```

نکته‌ها:

- **همه‌ی نوشتن‌ها در مرحله‌ی نوشتن نتیجه:** چه مقصد ثبات باشد چه حافظه. این سادگی برای گسترش با گمانه‌زنی حیاتی است (جلسه‌ی ۸-۶).
- **حلقه‌های «for all x»:** یعنی سخت‌افزار **انجمنی**: هر ایستگاه برچسب CDB را با Qj و Qk خودش مقایسه می‌کند. یک پخش روی CDB می‌تواند در یک سیکل به ده‌ها مقصد برسد و همه‌ی منتظرها در سیکل بعد شروع کنند.
- **ثبات فقط با آخرین نویسنده به‌روز می‌شود:** شرط `RegisterStat[x].Qi == r` یعنی اگر بعد از این دستور، دستور دیگری همان ثبات را مقصد گرفته باشد، این نتیجه در ثبات نوشته **نمی‌شود**. این همان حذف WAW است.
- **پرش‌ها:** چون بعد از صدور هیچ ترتیبی نگه داشته نمی‌شود، محدودیت «اجرا نکن تا پرش‌های قبلی تمام شوند» معمولاً با این پیاده می‌شود که اگر پرشی در خط لوله منتظر است، هیچ دستوری از مرحله‌ی صدور خارج نشود.

## ۶. مثال سیکل به سیکل اسلاید درس

اسلاید درس همین کد را سیکل به سیکل اجرا می‌کند، با تأخیرهای **بارگذاری ۲، جمع و تفریق ۲، ضرب ۱۰ و تقسیم ۴۰ سیکل**. خلاصه‌ی نهایی (ستون «اتمام اجرا» یعنی سیکلی که اجرا تمام می‌شود):

| دستور | صدور | اتمام اجرا | نوشتن نتیجه |
|---|---|---|---|
| دستور `L.D F6,34(R2)` | 1 | 3 | 4 |
| دستور `L.D F2,45(R3)` | 2 | 5 | 6 |
| دستور `MUL.D F0,F2,F4` | 3 | 16 | 17 |
| دستور `SUB.D F8,F6,F2` | 4 | 8 | 9 |
| دستور `DIV.D F10,F0,F6` | 5 | 58 | 59 |
| دستور `ADD.D F6,F8,F2` | 6 | 12 | 13 |

یک تفاوت جزئی: اسلاید دستور تفریق را `SUB.D F8,F6,F2` نوشته در حالی که کد کتاب `SUB.D F8,F2,F6` است. برای زمان‌بندی فرقی ندارد.

توضیح عددها. مدل اسلاید این فرض‌ها را دارد: بارگذاری‌ها یکی پس از دیگری از حافظه استفاده می‌کنند؛ فقط **یک جمع‌کننده** و **یک ضرب‌کننده** داریم؛ و یک واحد تا وقتی نتیجه‌ی دستور قبلی‌اش روی CDB نوشته نشده، آزاد نمی‌شود. دستوری که عملوندهایش را دارد و واحدش آزاد است، از سیکل بعد اجرا می‌کند:

- **بارگذاری‌ها:** اولی در سیکل‌های ۲ و ۳ و دومی در ۴ و ۵ از حافظه استفاده می‌کند. نوشتن‌ها در ۴ و ۶.
- **ضرب:** منتظر F2 است که در سیکل ۶ پخش می‌شود. اجرا در سیکل‌های ۷ تا ۱۶ (ده سیکل)، نوشتن در ۱۷.
- **تفریق:** آن هم منتظر F2 است. اجرا در ۷ و ۸، نوشتن در ۹. تفریق **قبل از ضرب** تمام می‌شود، با اینکه بعد از آن صادر شده: اجرای خارج از ترتیب.
- **جمع:** منتظر F8 است که در سیکل ۹ پخش می‌شود. جمع‌کننده تا سیکل ۹ در اختیار تفریق است و در سیکل ۱۰ آزاد می‌شود. اجرا در ۱۱ و ۱۲، نوشتن در ۱۳. جمع F6 را **قبل از** تقسیم (که F6 را می‌خواند) می‌نویسد: WAR بدون مشکل حذف شده.
- **تقسیم:** منتظر F0 است که در سیکل ۱۷ پخش می‌شود. ضرب‌کننده در ۱۸ آزاد می‌شود. اجرا در ۱۹ تا ۵۸ (چهل سیکل)، نوشتن در ۵۹.

وضعیت ثبات‌ها در پایان (سیکل ۵۹): F0 = حاصل ضرب، F2 = مقدار بارگذاری دوم، F6 = حاصل جمع، F8 = حاصل تفریق و F10 = حاصل تقسیم.

یک هشدار برای امتحان: قرارداد دقیق «یک سیکل اضافه» در منابع مختلف کمی فرق دارد. با قاعده‌ی کلی کتاب (اجرا از سیکلِ بعد از پخش عملوند، و واحدهای مستقل)، جمع در ۱۰ و ۱۱ و تقسیم در ۱۸ تا ۵۷ اجرا می‌شدند. در جواب امتحان، قرارداد خودت را صریح بنویس و به آن پایبند بمان.

## ۷. تمرین‌ها

<details>
<summary>تمرین ۱: عکس از وسط اجرا</summary>

**صورت:** در مثال اسلاید (بخش ۶)، در پایان سیکل ۱۰ وضعیت ایستگاه‌های Add2، Mult1 و Mult2 و فیلد Qi ثبات‌ها چیست؟

**جواب:**

- **ایستگاه Add2 (`ADD.D`):** Busy، هر دو عملوند آماده‌اند (حاصل تفریق در سیکل ۹ و F2 در سیکل ۶ پخش شده‌اند)، Qj و Qk صفر. منتظر آزاد شدن جمع‌کننده است و از سیکل ۱۱ اجرا می‌کند.
- **ایستگاه Mult1 (`MUL.D`):** Busy، در حال اجرا (سیکل چهارم از ده).
- **ایستگاه Mult2 (`DIV.D`):** Busy، Vk = حاصل بارگذاری اول، Qj = Mult1.
- **فیلد Qi:** F0 = Mult1، F6 = Add2، F10 = Mult2. ثبات‌های F2 و F8 آماده‌اند (Qi خالی).
</details>

<details>
<summary>تمرین ۲: دو جمع‌کننده</summary>

**صورت:** اگر در مثال اسلاید دو جمع‌کننده‌ی مستقل داشتیم، کدام سیکل‌ها عوض می‌شدند؟

**جواب:** فقط `ADD.D`: دیگر منتظر آزاد شدن جمع‌کننده‌ی تفریق نیست. عملوندش در سیکل ۹ پخش می‌شود، پس اجرا در ۱۰ و ۱۱ و نوشتن در ۱۲. زمان کل (که با تقسیم تعیین می‌شود) عوض نمی‌شود: مسیر بحرانی بارگذاری دوم، ضرب و تقسیم است.
</details>

<details>
<summary>تمرین ۳: چرا F6 در پایان مقدار ADD.D را دارد</summary>

**صورت:** دستور اول (`L.D F6`) و دستور آخر (`ADD.D F6`) هر دو در F6 می‌نویسند. در مثال اسلاید، اگر بارگذاری اول به خاطر عدم اصابت کش تا سیکل ۲۰ طول می‌کشید، آیا F6 در پایان مقدار درست را داشت؟

**جواب:** بله. در صدور `ADD.D` (سیکل ۶)، فیلد Qi ثبات F6 به Add2 تغییر کرده است. وقتی بارگذاری اول در سیکل ۲۰ نتیجه را پخش کند، شرط `RegisterStat[F6].Qi == Load1` برقرار نیست، پس در ثبات F6 نوشته **نمی‌شود**. ولی ایستگاه‌هایی که منتظر Load1 بودند (تفریق و تقسیم) مقدار را از CDB می‌گیرند. البته در این حالت `ADD.D` هم دیرتر اجرا می‌شود، چون به تفریق و آن به بارگذاری اول وابسته است.
</details>
