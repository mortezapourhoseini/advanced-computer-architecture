## ۱. صورت سؤال ۲ امتحان ۰۲-۰۳

حلقه‌ی زیر روی بردارهای ممیز شناور ۶۴ بیتی:

```c
for (i = 999; i >= 0; i = i - 1)
    x[i] = a * x[i] / y[i];
```

- **الف:** کد MIPS این حلقه را بنویس.
- **ب:** بارگذاری و ذخیره ۲ کلاک، محاسبات صحیح ۱ کلاک، جمع، ضرب و تقسیم ممیز شناور به ترتیب ۳، ۱۰ و ۲۰ کلاک زمان نیاز دارند. ۳ واحد بارگذاری و ذخیره، ۴ واحد جمع ممیز شناور و ۴ واحد ضرب و تقسیم ممیز شناور داریم. اجرای **دو تکرار** این حلقه را در جدولی با ستون‌های «صدور، اجرا، دسترسی حافظه، نوشتن CDB، منتظر چه» برای این حالت‌ها نشان بده:
    1. واکشی تک‌دستوری با روش توماسولو
    2. واکشی تک‌دستوری و اجرای گمانه‌ای
    3. واکشی دودستوری و اجرای گمانه‌ای

این سؤال دقیقاً همان قالب مثال جلسه‌ی ۸-۸ (شکل‌های ۳.۱۹ و ۳.۲۰ کتاب) را دارد.

## ۲. قسمت الف: کد MIPS

ثبات R1 آدرس `x[999]`، R2 آدرس `y[999]` و F2 مقدار a را دارد. R3 طوری تنظیم شده که حلقه بعد از عنصر صفر تمام شود.

```asm
Loop:   L.D     F0,0(R1)        ; x[i]
        MUL.D   F0,F0,F2        ; a * x[i]
        L.D     F4,0(R2)        ; y[i]
        DIV.D   F0,F0,F4        ; a * x[i] / y[i]
        S.D     F0,0(R1)        ; store x[i]
        DADDUI  R1,R1,#-8
        DADDUI  R2,R2,#-8
        BNE     R1,R3,Loop
```

مسیر بحرانی هر تکرار: بارگذاری x، ضرب (۱۰ سیکل)، تقسیم (۲۰ سیکل)، ذخیره. بقیه‌ی دستورات (بارگذاری y، به‌روزرسانی اشاره‌گرها، پرش) کوتاه‌اند.

## ۳. فرض‌ها

فرض‌های ما، با الگوی مثال کتاب (جلسه‌ی ۸-۸):

- **بارگذاری و ذخیره (۲ کلاک):** یک سیکل محاسبه‌ی آدرس و یک سیکل دسترسی حافظه. مثل کتاب، نتیجه‌ی بارگذاری در سیکل بعد از دسترسی حافظه روی CDB می‌رود. سه واحد آدرس و سه درگاه حافظه.
- **عملیات صحیح:** یک سیکل در واحد صحیح؛ پرش در واحد جدای پرش.
- **شروع اجرا:** دست‌کم یک سیکل بعد از صدور، و یک سیکل بعد از پخش آخرین عملوند روی CDB.
- **بدون گمانه‌زنی:** هیچ دستوری قبل از اجرای پرش قبلی‌اش اجرا را شروع نمی‌کند. ذخیره وقتی مقدارش آماده است حافظه را می‌نویسد.
- **با گمانه‌زنی:** پرش «انجام‌شده» پیش‌بینی می‌شود و درست است. دستورات بعد از پرش هم اجرا می‌شوند. ذخیره حافظه را در نهایی‌سازی می‌نویسد. نهایی‌سازی به ترتیب است، به تعداد پهنای صدور در هر سیکل، و دست‌کم یک سیکل بعد از نوشتن CDB.
- **تعداد CDB:** برابر با پهنای صدور. ایستگاه‌های رزرو و خانه‌های ROB به اندازه‌ی کافی.
- **صدور دوتایی:** دستور بعد از پرش در سیکل بعد صادر می‌شود (مثل جدول‌های کتاب).

- **چهار واحد ضرب و تقسیم:** ضرب تکرار دوم و تقسیم تکرار اول همزمان در دو واحد مختلف اجرا می‌شوند.
- **منتظر پرش:** بارگذاری تکرار دوم در سیکل ۹ صادر شده و پرش هم در سیکل ۹ اجرا شده. پس اینجا انتظار برای پرش هزینه‌ای ندارد.
- **ذخیره:** محاسبه‌ی آدرس زود (سیکل ۶) ولی نوشتن حافظه بعد از تقسیم (۳۷).

نکته‌های مهم:

- **اجرا عیناً مثل حالت ۱ است.** چرا گمانه‌زنی کمکی نکرده؟ چون با صدور تک‌دستوری، دستور بعد از پرش (سیکل ۹) زودتر از اجرای پرش (سیکل ۹) صادر نمی‌شود. پرش این حلقه به `DADDUI` وابسته است که زود حساب می‌شود، نه به داده‌ی ممیز شناور. پس گلوگاه **صدور** است، نه پرش.
- **نهایی‌سازی پشت تقسیم گیر می‌کند:** تقسیم تکرار اول در سیکل ۳۷ نهایی می‌شود و **همه‌ی** دستورات بعدی، حتی آن‌هایی که خیلی زودتر تمام شده‌اند، صبر می‌کنند. بارگذاری y تکرار اول در سیکل ۶ تمام شده ولی در ۱۷ نهایی می‌شود (پشت ضرب).
- **هزینه‌ی پنهان:** برای اینکه صدور تا سیکل ۱۶ ادامه یابد در حالی که اولین دستور تقسیم تا ۳۷ نهایی نمی‌شود، ROB باید دست‌کم حدود ۱۳ خانه (از تقسیم تکرار اول تا پرش تکرار دوم) داشته باشد. اگر ROB کوچک‌تر بود، صدور متوقف می‌شد.
- **فایده‌ی واقعی گمانه‌زنی اینجا:** استثنای دقیق. اگر تقسیم تکرار اول استثنا (مثلاً تقسیم بر صفر) بدهد، هیچ‌کدام از دستورات تکرار دوم نهایی نشده‌اند.

- **بارگذاری تکرار دوم در سیکل ۶ اجرا می‌شود:** همزمان با اجرای پرش تکرار اول، چون گمانه‌ای است. فقط به R1 جدید (پخش‌شده در سیکل ۵) نیاز دارد.
- **دو تکرار روی هم:** ضرب تکرار دوم در سیکل ۹ شروع می‌شود (در حالت ۱ در ۱۳) و تقسیم آن در ۲۰ (در حالت ۱ در ۲۴). پس تکرار دوم ۴ سیکل زودتر تمام می‌شود.
- **دو نهایی‌سازی در سیکل:** مثلاً در سیکل ۱۶ ضرب و بارگذاری y تکرار اول با هم نهایی می‌شوند.
- **صدور خیلی جلوتر از نهایی‌سازی است:** همه‌ی دستورات دو تکرار تا سیکل ۸ صادر شده‌اند ولی اولین تقسیم در ۳۷ نهایی می‌شود. صدور می‌تواند هر ۴ سیکل یک تکرار جلو برود، ولی ۴ واحد ضرب و تقسیم غیرخط لوله‌ای گلوگاه‌اند: هر تکرار ۳۰ سیکل کار (۱۰ ضرب و ۲۰ تقسیم) از این واحدها می‌خواهد، پس در حالت پایدار دست‌کم 30 / 4 = 7.5 سیکل برای هر تکرار. چون مسیر بحرانی هر تکرار حدود ۳۵ سیکل است، حدود 35 / 7.5 ≈ 5 تکرار همزمان در جریان‌اند: یعنی حدود ۴۰ خانه‌ی ROB و چندین ایستگاه رزرو برای ضرب و تقسیم لازم است.

درس‌ها:

- **صدور دوتایی به‌علاوه‌ی گمانه‌زنی** اجازه می‌دهد تکرارها روی هم بیفتند و زمان کل کم شود.
- **در حالت پایدار،** گلوگاه واقعی این حلقه واحدهای ضرب و تقسیم‌اند، نه صدور یا پرش. هر روشی که آن‌ها را آزاد کند (مثلاً واحد تقسیم خط لوله‌ای یا محاسبه‌ی a / y[i] به شکل ضرب در وارون، اگر دقت اجازه دهد) بیشترین اثر را دارد.

## ۸. یک شبیه‌ساز برای بررسی جواب

این برنامه‌ی پایتون همان مدل زمان‌بندی این جلسه را پیاده می‌کند. با آن جدول‌های شکل‌های ۳.۱۹ و ۳.۲۰ کتاب (جلسه‌ی ۸-۸) و سه جدول بالا عیناً بازتولید می‌شوند:

```python
import re

def parse(line):
    """Return (class, destination, sources, base register) for one instruction."""
    line = line.split(';')[0].strip()
    op, args = line.split(None, 1)
    a = [x.strip() for x in args.split(',')]
    op = op.upper()
    mem = lambda s: re.search(r'\((\w+)\)', s).group(1)
    if op in ('L.D', 'LD'):
        return 'load', a[0], [], mem(a[1])
    if op in ('S.D', 'SD'):
        return 'store', None, [a[0]], mem(a[1])
    if op in ('BNE', 'BEQ'):
        return 'branch', None, a[:2], None
    if op in ('ADD.D', 'SUB.D'):
        return 'fpadd', a[0], a[1:], None
    if op == 'MUL.D':
        return 'fpmul', a[0], a[1:], None
    if op == 'DIV.D':
        return 'fpdiv', a[0], a[1:], None
    return 'int', a[0], [x for x in a[1:] if not x.startswith('#')], None

# which unit executes each class; loads also use a memory unit after address calculation
UNIT = {'load': 'addr', 'store': 'addr', 'int': 'int', 'branch': 'br',
        'fpadd': 'add', 'fpmul': 'mul', 'fpdiv': 'mul'}

def simulate(program, width, speculate, latency, units, cdbs):
    busy = {}                 # (unit, k) -> set of busy cycles
    cdb_use = {}              # cycle -> number of results broadcast
    commits = {}              # cycle -> number of commits
    writer = {}               # register -> row of its latest producer
    rows = []
    cycle, used, last_branch_exec, last_commit = 1, 0, None, 0

    def take_unit(u, start, length):
        while True:
            for k in range(units[u]):
                occ = busy.setdefault((u, k), set())
                if not any(c in occ for c in range(start, start + length)):
                    occ.update(range(start, start + length))
                    return start
            start += 1

    def ready(reg):           # first cycle a source value can be used
        return writer[reg]['cdb'] + 1 if reg in writer else 0

    for it, text in program:
        cls, dst, srcs, base = parse(text)
        r = {'it': it, 'text': text, 'cls': cls}
        # issue: in order, width per cycle, an instruction after a branch starts a new bundle
        if used == width or (rows and rows[-1]['cls'] == 'branch'):
            cycle, used = cycle + 1, 0
        r['issue'] = cycle
        used += 1
        # execute: after issue, operands ready, (no speculation) after earlier branches
        start = cycle + 1
        for s in ([base] if base else []) + ([] if cls == 'store' else srcs):
            start = max(start, ready(s))
        if not speculate and last_branch_exec is not None:
            start = max(start, last_branch_exec + 1)
        L = latency[cls]
        start = take_unit(UNIT[cls], start, L)
        end = start + L - 1
        r['exec'] = (start, end)
        if cls == 'load':                               # memory access after address
            m = take_unit('mem', end + 1, latency['mem'])
            r['mem'] = (m, m + latency['mem'] - 1)
            end = r['mem'][1]
        if cls == 'store' and not speculate:            # store writes memory when value ready
            m = take_unit('mem', max(end + 1, ready(srcs[0])), latency['mem'])
            r['mem'] = (m, m + latency['mem'] - 1)
        r['cdb'] = None
        if dst:                                         # write result on a CDB
            w = end + 1
            while cdb_use.get(w, 0) >= cdbs:
                w += 1
            cdb_use[w] = cdb_use.get(w, 0) + 1
            r['cdb'] = w
            writer[dst] = r
        if cls == 'branch':
            last_branch_exec = end
        if speculate:                                   # commit: in order, width per cycle
            c = max(last_commit, end + 1 if r['cdb'] is None else r['cdb'] + 1)
            if cls == 'store':
                c = max(c, ready(srcs[0]))
            while commits.get(c, 0) >= width:
                c += 1
            commits[c] = commits.get(c, 0) + 1
            r['commit'] = last_commit = c
        rows.append(r)
    return rows

def show(rows):
    span = lambda p: '' if not p else (str(p[0]) if p[0] == p[1] else f'{p[0]}-{p[1]}')
    for r in rows:
        print(f"{r['it']} {r['text']:<18} issue={r['issue']:<3} exec={span(r['exec']):<6} "
              f"mem={span(r.get('mem')):<6} cdb={r['cdb'] or '':<4} commit={r.get('commit', '')}")

body = ['L.D F0,0(R1)', 'MUL.D F0,F0,F2', 'L.D F4,0(R2)', 'DIV.D F0,F0,F4',
        'S.D F0,0(R1)', 'DADDUI R1,R1,#-8', 'DADDUI R2,R2,#-8', 'BNE R1,R3,Loop']
program = [(it, line) for it in (1, 2) for line in body]
latency = {'load': 1, 'mem': 1, 'store': 1, 'int': 1, 'branch': 1,
           'fpadd': 3, 'fpmul': 10, 'fpdiv': 20}
units = {'addr': 3, 'mem': 3, 'int': 1, 'br': 1, 'add': 4, 'mul': 4}
for width, spec in ((1, False), (1, True), (2, True)):
    print(f'--- issue width {width}, speculation {spec}')
    show(simulate(program, width, spec, latency, units, cdbs=width))
```

برای بازتولید جدول‌های کتاب، بدنه‌ی حلقه را عوض کن و از `units = {'addr': 1, 'mem': 1, 'int': 1, 'br': 1}`، تأخیر یک سیکلی برای همه و `cdbs=2` استفاده کن. این مدل ساده است: تعداد ایستگاه‌های رزرو و خانه‌های ROB نامحدود فرض شده و همه‌ی پیش‌بینی‌ها درست‌اند.

## ۹. تمرین‌ها

<details>
<summary>تمرین ۱: تقسیم خط لوله‌ای</summary>

**صورت:** در حالت ۳، اگر فقط **یک** واحد ضرب و تقسیم داشتیم، چه چیزی عوض می‌شد؟

**جواب:** ضرب تکرار اول واحد را در ۵ تا ۱۴ می‌گیرد. ضرب تکرار دوم از سیکل ۹ آماده است و منتظر واحد می‌ماند. در سیکل ۱۵ واحد آزاد می‌شود و **فقط** ضرب تکرار دوم آماده است (تقسیم تکرار اول تازه در سیکل ۱۵ عملوندش روی CDB پخش می‌شود و از ۱۶ آماده است). پس ضرب تکرار دوم واحد را در ۱۵ تا ۲۴ می‌گیرد، تقسیم تکرار اول مجبور است تا ۲۵ صبر کند (۲۵ تا ۴۴) و تقسیم تکرار دوم بعد از آن (۴۵ تا ۶۴). نکته‌ی جالب: یک دستور از تکرار **بعدی** مسیر بحرانی تکرار **قبلی** را ۹ سیکل عقب انداخت. زمان‌بند ساده‌ی «هر کس آماده بود» همیشه بهترین انتخاب را نمی‌کند. نتیجه‌ی کلی: منابع اجرایی باید با پهنای صدور و طول زنجیره‌ها متناسب باشند، وگرنه گمانه‌زنی و صدور دوتایی سودی نمی‌دهند.
</details>

<details>
<summary>تمرین ۲: نسخه‌ی بدون گمانه‌زنی دوصدوری</summary>

**صورت:** با شبیه‌ساز بخش ۸، حالت «دوصدوری بدون گمانه‌زنی» را اجرا کن. تقسیم تکرار دوم کی تمام می‌شود؟

**جواب:** با `simulate(program, 2, False, latency, units, cdbs=2)`: بارگذاری تکرار دوم تا اجرای پرش (سیکل ۶) صبر می‌کند و در ۷ اجرا می‌شود؛ ضرب در ۱۰ تا ۱۹ و تقسیم در ۲۱ تا ۴۰. یعنی یک سیکل دیرتر از حالت ۳. در این حلقه پرش زود حل می‌شود، پس سود گمانه‌زنی کوچک است. برعکس مثال جلسه‌ی ۸-۸ که پرش به داده‌ی بارگذاری‌شده وابسته بود.
</details>
