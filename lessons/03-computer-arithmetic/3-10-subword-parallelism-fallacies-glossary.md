## ۱. موازی‌سازی زیرکلمه‌ای

پردازش تصویر، صدا و ویدیو معمولاً روی داده‌های کوتاه کار می‌کند: پیکسل‌های ۸ بیتی و نمونه‌های صوتی ۱۶ بیتی. اگر جمع‌کننده‌ی ۱۲۸ بیتی داشته باشیم، می‌توانیم آن را طوری طراحی کنیم که رقم نقلی را در مرزهای مشخصی قطع کند. آن‌وقت همان جمع‌کننده همزمان این‌ها را جمع می‌کند:

| اندازه‌ی عنصر | تعداد عنصر در ۱۲۸ بیت |
|---|---|
| عنصر ۸ بیتی | 16 |
| عنصر ۱۶ بیتی | 8 |
| عنصر ۳۲ بیتی | 4 |
| عنصر ۶۴ بیتی | 2 |

به این ایده **موازی‌سازی زیرکلمه‌ای (Subword parallelism)** یا **SIMD کوتاه** می‌گوییم. SIMD یعنی یک دستور روی چند داده (Single Instruction, Multiple Data). هزینه‌ی سخت‌افزار کم است: فقط باید زنجیره‌ی رقم نقلی در مرزها قطع‌شدنی باشد. ولی کارایی در کدهای مناسب چند برابر می‌شود. در بخش ۹ نسخه‌ی کامل این ایده یعنی **معماری برداری** و **GPU** را می‌بینیم.

## ۲. دستورات SIMD در x86: از MMX تا AVX

تاریخچه‌ی کوتاه:

| سال | توسعه | ثبات‌ها | نکته |
|---|---|---|---|
| سال ۱۹۹۷ | دستورات MMX | هشت ثبات ۶۴ بیتی | ثبات‌های ممیز شناور x87 را قرض می‌گرفت، فقط عدد صحیح |
| سال ۱۹۹۹ | دستورات SSE | هشت ثبات ۱۲۸ بیتی XMM | چهار عدد دقت ساده |
| سال ۲۰۰۱ | دستورات SSE2 | همان ثبات‌ها، بعداً ۱۶ ثبات در x86-64 | دو عدد دقت مضاعف |
| سال ۲۰۱۱ | دستورات AVX | شانزده ثبات ۲۵۶ بیتی YMM | چهار عدد دقت مضاعف، سه‌عملوندی |
| سال ۲۰۱۳ | دستورات AVX2 و FMA | همان | ضرب و جمع ترکیبی، صحیح ۲۵۶ بیتی |
| سال ۲۰۱۶ | دستورات AVX-512 | سی‌ودو ثبات ۵۱۲ بیتی ZMM | هشت عدد دقت مضاعف |

سؤال امتحان ۹۵-۹۶ «معرفی واحد MMX در پردازنده‌های اینتل» را هم با این جدول می‌توان جواب داد: MMX اولین توسعه‌ی SIMD اینتل بود که با هشت ثبات ۶۴ بیتی، عملیات صحیح روی ۸ بایت، ۴ نیم‌کلمه یا ۲ کلمه را با یک دستور انجام می‌داد. حساب اشباعی هم داشت. عیب بزرگش این بود که ثبات‌های ممیز شناور را قرض می‌گرفت، پس نمی‌شد همزمان با برنامه‌ی ممیز شناور از آن استفاده کرد. برای همین SSE ثبات‌های جدا آورد.

### نام‌گذاری دستورات

نام دستورات SSE و AVX یک الگو دارد. مثلاً در `addpd`:

- **عمل:** add.
- **حرف p:** یعنی Packed، عمل روی همه‌ی عناصر بسته‌شده در ثبات. در مقابل، حرف s یعنی Scalar و فقط عنصر پایین.
- **حرف d:** یعنی Double. حرف s در انتها یعنی Single.

| دستور x86 | معنی |
|---|---|
| دستور `movapd` | بارگذاری یا ذخیره‌ی بسته‌ی دقت مضاعف ردیف‌شده |
| دستور `addsd` | جمع یک عدد دقت مضاعف (اسکالر) |
| دستور `addpd` | جمع دو عدد دقت مضاعف در XMM |
| دستور `vaddpd` | جمع چهار عدد دقت مضاعف در YMM (نسخه‌ی AVX) |
| دستور `vmulpd` | ضرب چهار عدد دقت مضاعف |
| دستور `vbroadcastsd` | کپی یک عدد در هر چهار جای ثبات YMM |

## ۳. سریع‌تر کردن ضرب ماتریس با AVX

کتاب COD در بخش ۳.۸ برنامه‌ی **DGEMM** (ضرب ماتریس دقت مضاعف) را با AVX سریع می‌کند. نسخه‌ی کتاب ماتریس را **ستونی (Column-major)** ذخیره می‌کند، یعنی خانه‌ی [i][j] در جای `i + j*n` است. این همان قراردادی است که کتابخانه‌های Fortran و BLAS دارند.

نسخه‌ی معمولی:

```c
void dgemm(int n, double *A, double *B, double *C)
{
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j) {
            double cij = C[i + j * n];          /* cij = C[i][j] */
            for (int k = 0; k < n; k++)
                cij += A[i + k * n] * B[k + j * n];
            C[i + j * n] = cij;                 /* C[i][j] = cij */
        }
}
```

نسخه‌ی AVX کتاب، با **توابع درونی (Intrinsics)** که هر کدام به یک دستور AVX ترجمه می‌شوند:

```c
#include <x86intrin.h>
void dgemm_avx(int n, double *A, double *B, double *C)
{
    for (int i = 0; i < n; i += 4)
        for (int j = 0; j < n; j++) {
            __m256d c0 = _mm256_load_pd(C + i + j * n);     /* c0 = C[i..i+3][j] */
            for (int k = 0; k < n; k++)
                c0 = _mm256_add_pd(c0,                      /* c0 += A[i..i+3][k] * B[k][j] */
                        _mm256_mul_pd(_mm256_load_pd(A + i + k * n),
                                      _mm256_broadcast_sd(B + k + j * n)));
            _mm256_store_pd(C + i + j * n, c0);             /* C[i..i+3][j] = c0 */
        }
}
```

ایده‌ی اصلی:

- **چهار عنصر همزمان:** حلقه‌ی بیرونی ۴ تا ۴ تا جلو می‌رود و هر بار چهار خانه‌ی پشت سر هم یک ستون C را با هم حساب می‌کند.
- **کپی یک عدد:** عدد `B[k][j]` برای هر چهار خانه یکی است. پس با `broadcast` در هر چهار جای ثبات کپی می‌شود.
- **حلقه‌ی داخلی:** داخل حلقه‌ی داخلی فقط سه دستور اصلی AVX اجرا می‌شود: بارگذاری، ضرب و جمع. کتاب نشان می‌دهد کامپایلر آن را به دستوراتی مثل `vmovapd`، `vbroadcastsd`، `vmulpd` و `vaddpd` ترجمه می‌کند.

نتیجه‌ی کتاب: برای ماتریس ۳۲ × ۳۲ روی پردازنده‌ی Core i7 (Sandy Bridge)، نسخه‌ی AVX حدود **۳.۸۵ برابر** سریع‌تر است. انتظار ۴ برابر بود، چون هر دستور چهار عنصر را پردازش می‌کند. کمی کمتر است، چون بخش‌هایی از برنامه (مثل محاسبه‌ی آدرس و کنترل حلقه) موازی نشده‌اند. این همان قانون امدال بخش ۱ است.

## ۴. آزمایش عملی روی لینوکس

این آزمایش را روی لینوکس مینت خودت انجام بده. اول کامپایلر را نصب کن:

```bash
sudo apt install build-essential
grep -o -m1 avx /proc/cpuinfo
```

اگر دستور دوم کلمه‌ی `avx` را چاپ کرد، پردازنده‌ات AVX دارد. حالا فایل `dgemm.c` را با این محتوا بساز. دو تابع بالا را در آن بگذار و این تابع `main` را اضافه کن:

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <x86intrin.h>

/* put dgemm and dgemm_avx here */

static double now(void)
{
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return t.tv_sec + t.tv_nsec * 1e-9;
}

int main(void)
{
    int n = 512;
    double *A  = aligned_alloc(32, n * n * sizeof(double));
    double *B  = aligned_alloc(32, n * n * sizeof(double));
    double *C1 = aligned_alloc(32, n * n * sizeof(double));
    double *C2 = aligned_alloc(32, n * n * sizeof(double));
    for (int i = 0; i < n * n; i++) {
        A[i] = rand() % 10; B[i] = rand() % 10; C1[i] = C2[i] = 0;
    }
    double t0 = now(); dgemm(n, A, B, C1);
    double t1 = now(); dgemm_avx(n, A, B, C2);
    double t2 = now();
    for (int i = 0; i < n * n; i++)
        if (C1[i] != C2[i]) { printf("mismatch at %d\n", i); return 1; }
    double flops = 2.0 * n * n * n;
    printf("scalar: %.3f s  %.2f GFLOPS\n", t1 - t0, flops / (t1 - t0) / 1e9);
    printf("avx   : %.3f s  %.2f GFLOPS\n", t2 - t1, flops / (t2 - t1) / 1e9);
    printf("speedup: %.2f\n", (t1 - t0) / (t2 - t1));
    return 0;
}
```

کامپایل و اجرا:

```bash
gcc -O3 -mavx -fno-tree-vectorize dgemm.c -o dgemm
./dgemm
```

گزینه‌ی `-fno-tree-vectorize` جلوی برداری‌سازی خودکار نسخه‌ی معمولی را می‌گیرد تا مقایسه منصفانه باشد. روی ماشینی که من آزمایش کردم، نسخه‌ی AVX حدود **۳.۵ برابر** سریع‌تر بود و هر دو نسخه نتیجه‌ی یکسان دادند. عدد دقیق روی کامپیوتر تو فرق می‌کند.

دو آزمایش پیشنهادی:

- **برداری‌سازی خودکار:** گزینه‌ی `-fno-tree-vectorize` را بردار و دوباره اجرا کن. ببین کامپایلر خودش چقدر نسخه‌ی معمولی را سریع می‌کند.
- **اندازه‌ی ماتریس:** مقدار `n` را به ۶۴، ۲۵۶ و ۱۰۲۴ تغییر بده. با بزرگ شدن ماتریس، داده‌ها دیگر در کش جا نمی‌شوند و کارایی هر دو افت می‌کند. این موضوع بخش ۶ است.

در ویندوز ساده‌ترین راه این است که همین دستورات را داخل WSL (زیرسیستم لینوکس ویندوز) اجرا کنی.

## ۵. ممیز شناور در RISC-V و ARM

### معماری RISC-V

- **توسعه‌های F و D:** دستورات ممیز شناور دقت ساده و مضاعف در توسعه‌های جداگانه‌ی F و D هستند.
- **ثبات‌های جدا:** سی‌ودو ثبات `f0` تا `f31`. در توسعه‌ی D هر ثبات ۶۴ بیتی است و دیگر جفت ثبات لازم نیست.
- **نام دستورات:** مثل `fadd.d`، `fmul.s`، `flw`، `fld` و `fsd`.
- **مقایسه بدون پرچم:** دستورات `feq.d`، `flt.d` و `fle.d` نتیجه‌ی ۰ یا ۱ را در یک **ثبات صحیح** می‌نویسند. بعد با `bne` یا `beq` پرش می‌کنیم. یعنی RISC-V پرچم شرط ممیز شناور ندارد.
- **ضرب و جمع ترکیبی:** دستورات `fmadd`، `fmsub`، `fnmadd` و `fnmsub` جزو پایه‌ی F و D هستند.
- **حالت گرد کردن:** هر دستور ممیز شناور یک فیلد سه‌بیتی برای حالت گرد کردن دارد.

### معماری ARM

- **نسخه‌ی ARMv7:** واحد ممیز شناور VFP با ۳۲ ثبات ۶۴ بیتی (`d0` تا `d31`) که دقت ساده‌ها نیمه‌های آن‌ها هستند (`s0` تا `s31`). واحد SIMD با نام NEON از همان ثبات‌ها به شکل ۱۲۸ بیتی استفاده می‌کند.
- **نسخه‌ی ARMv8:** سی‌ودو ثبات ۱۲۸ بیتی `v0` تا `v31` برای ممیز شناور و SIMD. دستورات اسکالر مثل `fadd d0, d1, d2` و دستورات برداری مثل `fadd v0.2d, v1.2d, v2.2d`. مقایسه پرچم‌های معمولی را تنظیم می‌کند.

## ۶. باورهای غلط و دام‌ها

### باور غلط: شیفت به راست همان تقسیم بر توان دو است

شیفت به چپ به اندازه‌ی i بیت واقعاً ضرب در 2 به توان i است. ولی شیفت به راست برای اعداد منفی علامت‌دار با تقسیم فرق دارد. مثال کتاب: −5 تقسیم بر 4.

```text
-5           = 1111 1111 1111 1111 1111 1111 1111 1011
srl by 2     = 0011 1111 1111 1111 1111 1111 1111 1110   (huge positive, wrong)
sra by 2     = 1111 1111 1111 1111 1111 1111 1111 1110   (-2)
-5 / 4 in C  = -1
```

شیفت منطقی کاملاً غلط است. شیفت حسابی −2 می‌دهد، یعنی به سمت منفی بی‌نهایت گرد می‌کند، ولی تقسیم C به سمت صفر گرد می‌کند و −1 می‌دهد. برای همین کامپایلر برای تقسیم علامت‌دار بر توان دو، قبل از شیفت یک تصحیح اضافه می‌کند.

### دام: جمع ممیز شناور شرکت‌پذیر نیست

در جلسه‌ی ۳-۹ دیدیم c + (a + b) با (c + a) + b می‌تواند فرق کند. چون اعداد ممیز شناور تقریبی‌اند و برد بزرگی دارند، ترتیب جمع مهم است.

### باور غلط: روش‌های موازی‌سازی که برای اعداد صحیح جواب می‌دهند، برای ممیز شناور هم جواب می‌دهند

وقتی یک جمع بزرگ را بین چند هسته تقسیم می‌کنیم، ترتیب جمع‌ها عوض می‌شود. برای اعداد صحیح این مهم نیست. ولی برای ممیز شناور، به دلیل دام قبلی، نتیجه ممکن است با نسخه‌ی ترتیبی فرق کند و حتی در هر اجرا متفاوت باشد. برنامه‌نویس برنامه‌ی موازی باید بداند نتیجه‌ی کمی متفاوت قابل قبول است یا نه.

### باور غلط: فقط ریاضی‌دانان نظری به دقت ممیز شناور اهمیت می‌دهند

در سال ۱۹۹۴ پروفسور توماس نایسلی (Thomas Nicely) متوجه شد که پردازنده‌ی پنتیوم اینتل بعضی تقسیم‌ها را اشتباه حساب می‌کند. دلیلش پنج خانه‌ی خالی در جدول جست‌وجوی الگوریتم SRT بود (جلسه‌ی ۳-۶). اینتل اول گفت خطا خیلی نادر است و فقط برای کاربران خاص اهمیت دارد. ولی فشار عمومی آن‌قدر زیاد شد که اینتل مجبور شد همه‌ی تراشه‌ها را تعویض کند. هزینه‌ی این ماجرا حدود ۵۰۰ میلیون دلار بود.

### دام: ثابت دستور addiu با علامت گسترش می‌یابد

کتاب یادآوری می‌کند که با وجود حرف u در نام، دستور `addiu` ثابت ۱۶ بیتی را **با علامت** گسترش می‌دهد. حرف u فقط یعنی سرریز بررسی نمی‌شود. همین‌طور `sltiu` ثابتش را با علامت گسترش می‌دهد و بعد مقایسه‌ی بدون علامت می‌کند.

## ۷. جمع‌بندی بخش

- **بیت‌ها معنای ذاتی ندارند:** مکمل دو برای صحیح‌ها و IEEE 754 برای ممیز شناور دو قرارداد اصلی‌اند. دستورات تعیین می‌کنند یک الگوی بیتی چطور تفسیر شود.
- **واحد ALU:** با مالتی‌پلکسر و تکرار یک واحد یک‌بیتی ساخته می‌شود. تفریق با مکمل دو، و slt با بیت علامت و سرریز.
- **جمع سریع:** پیش‌بینی رقم نقلی تأخیر را از خطی به لگاریتمی کاهش می‌دهد.
- **ضرب:** جمع و شیفت؛ بوث برای اعداد علامت‌دار؛ درخت جمع‌کننده برای سرعت.
- **تقسیم:** تفریق و شیفت با بازیابی؛ سخت‌تر از ضرب موازی می‌شود.
- **ممیز شناور:** علامت، توان بایاس‌دار و کسر با بیت پنهان؛ مقادیر ویژه؛ گرد کردن با بیت‌های G، R و S.
- **موازی‌سازی زیرکلمه‌ای:** یک دستور روی چند داده‌ی کوتاه، با هزینه‌ی سخت‌افزاری کم.

دستوراتی که در این بخش به مجموعه‌ی MIPS اضافه شدند:

| دسته | دستورات |
|---|---|
| ضرب و تقسیم صحیح | `mult`، `multu`، `div`، `divu`، `mfhi`، `mflo` |
| حساب ممیز شناور | `add.s/d`، `sub.s/d`، `mul.s/d`، `div.s/d` |
| انتقال ممیز شناور | `lwc1`، `swc1`، `ldc1`، `sdc1`، `mtc1`، `mfc1` |
| مقایسه و پرش ممیز شناور | `c.x.s/d`، `bc1t`، `bc1f` |

| نرمال‌شده | Normalized |
| کسر، مانتیس | Fraction, Significand |
| توان بایاس‌دار | Biased exponent |
| بیت پنهان | Hidden bit |
| دقت ساده، دقت مضاعف | Single precision, Double precision |
| سرریز، زیرریز | Overflow, Underflow |
| عدد نرمال‌نشده | Denormalized (subnormal) number |
| نه‌عدد | Not a Number (NaN) |
| بیت محافظ، بیت گرد، بیت چسبنده | Guard, Round, Sticky bit |
| واحد کمترین رقم | Unit in the last place (ULP) |
| ضرب و جمع ترکیبی | Fused multiply-add (FMA) |
| موازی‌سازی زیرکلمه‌ای | Subword parallelism |
| یک دستور، چند داده | Single instruction, multiple data (SIMD) |

## ۹. تمرین‌ها

<details>
<summary>تمرین ۱: SIMD ساده</summary>

**صورت:** دو آرایه‌ی ۱۰۲۴ عنصری از پیکسل‌های ۸ بیتی را با دستورات SIMD ۲۵۶ بیتی جمع اشباعی می‌کنیم. چند دستور جمع لازم است؟ با دستورات اسکالر چطور؟

**جواب:** هر ثبات ۲۵۶ بیتی ۳۲ پیکسل ۸ بیتی دارد. پس 1024 / 32 = 32 دستور جمع لازم است. با دستورات اسکالر ۱۰۲۴ جمع، به‌علاوه‌ی مقایسه و پرش برای اشباع هر کدام، لازم است.
</details>

<details>
<summary>تمرین ۲: تقسیم با شیفت</summary>

**صورت:** کد MIPS بنویس که تقسیم علامت‌دار `$s0` بر ۸ را مثل زبان C (گرد به سمت صفر) با شیفت انجام دهد.

**جواب:** اگر عدد منفی است، قبل از شیفت 8 − 1 = 7 به آن اضافه می‌کنیم. این کار بدون پرش هم ممکن است:

```asm
        sra  $t1, $s0, 31      # t1 = -1 if negative, else 0
        srl  $t1, $t1, 29      # t1 = 7 if negative, else 0
        addu $t0, $s0, $t1     # t0 = s0 + bias
        sra  $t0, $t0, 3       # t0 = s0 / 8 (rounded toward zero)
```

مثلاً برای −5: بایاس ۷ است، −5 + 7 = 2 و شیفت حسابی ۳ بیتی آن صفر می‌دهد که همان −5/8 در C است.
</details>

<details>
<summary>تمرین ۳: قانون امدال و SIMD</summary>

**صورت:** در یک برنامه ۸۰٪ زمان در حلقه‌ای است که با AVX چهار برابر سریع می‌شود. تسریع کل چقدر است؟

**جواب:** با قانون امدال:

```math
\text{Speedup} = \frac{1}{0.2 + \frac{0.8}{4}} = \frac{1}{0.4} = 2.5
```
</details>
