## ۱. روش ترجمه‌ی یک رویه

در جلسه‌های قبل تکه‌های کوچک کد را ترجمه کردیم. حالا یک برنامه‌ی کامل را از C به اسمبلی MIPS می‌بریم. کتاب برای ترجمه‌ی هر رویه سه مرحله پیشنهاد می‌کند:

1. **تخصیص ثبات:** متغیرهای برنامه را به ثبات‌ها نسبت بده.
2. **ترجمه‌ی بدنه:** کد بدنه‌ی رویه را بنویس.
3. **حفظ ثبات‌ها:** ثبات‌هایی را که در طول فراخوانی باید حفظ شوند، ذخیره و بازیابی کن.

برنامه‌ی نمونه، مرتب‌سازی درجی (یا حبابی، طبق نام کتاب) روی آرایه‌ای از اعداد صحیح است. این برنامه دو رویه دارد: `swap` که دو عنصر را جابه‌جا می‌کند و `sort` که آرایه را مرتب می‌کند.

## ۲. رویه‌ی swap

```c
void swap(int v[], int k)
{
    int temp;
    temp = v[k];
    v[k] = v[k+1];
    v[k+1] = temp;
}
```

### مرحله‌ی ۱: تخصیص ثبات

دو آرگومان داریم: `v` در `$a0` و `k` در `$a1`. متغیر `temp` را در `$t0` می‌گذاریم. چون `swap` رویه‌ی برگ است، ثبات‌های `$t` کافی‌اند.

### مرحله‌ی ۲: بدنه

آدرس `v[k]` برابر `v + 4k` است:

```asm
swap:   sll  $t1, $a1, 2       # t1 = k * 4
        add  $t1, $a0, $t1     # t1 = v + (k * 4) = &v[k]
        lw   $t0, 0($t1)       # temp = v[k]
        lw   $t2, 4($t1)       # t2 = v[k+1]
        sw   $t2, 0($t1)       # v[k] = t2
        sw   $t0, 4($t1)       # v[k+1] = temp
        jr   $ra               # return
```

به جابه‌جایی ۴ در دسترسی به `v[k+1]` دقت کن. عنصر بعدی دقیقاً ۴ بایت جلوتر است، پس دوباره حساب کردن آدرس لازم نیست.

### مرحله‌ی ۳: حفظ ثبات‌ها

چون فقط از ثبات‌های `$t` استفاده کردیم و رویه‌ی دیگری صدا نمی‌زنیم، هیچ چیزی لازم نیست ذخیره شود. این ساده‌ترین حالت است.

اسلاید درس همین رویه را با شماره‌ی ثبات‌ها و دستور `muli` نوشته است. نسخه‌ی بالا با `sll` همان کار را بدون ضرب انجام می‌دهد.

## ۳. رویه‌ی sort

```c
void sort(int v[], int n)
{
    int i, j;
    for (i = 0; i < n; i += 1) {
        for (j = i - 1; j >= 0 && v[j] > v[j + 1]; j -= 1) {
            swap(v, j);
        }
    }
}
```

### مرحله‌ی ۱: تخصیص ثبات

| متغیر | ثبات | دلیل |
|---|---|---|
| آرگومان `v` | ابتدا `$a0`، بعد `$s2` | باید `$a0` را برای `swap` آزاد کنیم |
| آرگومان `n` | ابتدا `$a1`، بعد `$s3` | همین دلیل |
| متغیر `i` | ثبات `$s0` | باید بعد از `swap` حفظ شود |
| متغیر `j` | ثبات `$s1` | باید بعد از `swap` حفظ شود |

### مرحله‌ی ۲: بدنه

**حلقه‌ی بیرونی.** حلقه‌ی `for` سه بخش دارد: مقداردهی اولیه، آزمون و افزایش.

```asm
        move $s0, $zero        # i = 0
for1tst:
        slt  $t0, $s0, $s3     # t0 = 0 if i >= n
        beq  $t0, $zero, exit1 # go to exit1 if i >= n
        ...                    # body of the outer loop
        addi $s0, $s0, 1       # i += 1
        j    for1tst           # jump to test of outer loop
exit1:
```

**حلقه‌ی درونی.** این حلقه دو شرط دارد که با `&&` به هم وصل شده‌اند. اگر هر کدام نادرست باشد، از حلقه خارج می‌شویم:

```asm
        addi $s1, $s0, -1      # j = i - 1
for2tst:
        slti $t0, $s1, 0       # t0 = 1 if j < 0
        bne  $t0, $zero, exit2 # go to exit2 if j < 0
        sll  $t1, $s1, 2       # t1 = j * 4
        add  $t2, $s2, $t1     # t2 = &v[j]
        lw   $t3, 0($t2)       # t3 = v[j]
        lw   $t4, 4($t2)       # t4 = v[j+1]
        slt  $t0, $t4, $t3     # t0 = 0 if v[j+1] >= v[j]
        beq  $t0, $zero, exit2 # go to exit2 if v[j+1] >= v[j]
        ...                    # body of the inner loop
        addi $s1, $s1, -1      # j -= 1
        j    for2tst           # jump to test of inner loop
exit2:
```

شرط `v[j] > v[j+1]` معادل `v[j+1] < v[j]` است. پس `slt $t0, $t4, $t3` را نوشتیم.

**فراخوانی swap.** بدنه‌ی حلقه‌ی درونی فقط یک فراخوانی است:

```asm
        move $a0, $s2          # 1st parameter of swap is v
        move $a1, $s1          # 2nd parameter of swap is j
        jal  swap
```

### مرحله‌ی ۳: حفظ ثبات‌ها

رویه‌ی `sort` خودش صدا زده می‌شود و `swap` را صدا می‌زند. پس باید `$ra` را ذخیره کند. همچنین از `$s0` تا `$s3` استفاده می‌کند که باید حفظ شوند. در کل ۵ ثبات:

```asm
sort:   addi $sp, $sp, -20     # make room on stack for 5 registers
        sw   $ra, 16($sp)      # save $ra
        sw   $s3, 12($sp)      # save $s3
        sw   $s2, 8($sp)       # save $s2
        sw   $s1, 4($sp)       # save $s1
        sw   $s0, 0($sp)       # save $s0
```

و در انتها همه را برمی‌گرداند.

### کد کامل

```asm
# ---------- saving registers ----------
sort:   addi $sp, $sp, -20
        sw   $ra, 16($sp)
        sw   $s3, 12($sp)
        sw   $s2, 8($sp)
        sw   $s1, 4($sp)
        sw   $s0, 0($sp)
# ---------- procedure body ----------
        move $s2, $a0          # copy parameter v into $s2
        move $s3, $a1          # copy parameter n into $s3
        move $s0, $zero        # i = 0
for1tst:
        slt  $t0, $s0, $s3     # i < n ?
        beq  $t0, $zero, exit1
        addi $s1, $s0, -1      # j = i - 1
for2tst:
        slti $t0, $s1, 0       # j < 0 ?
        bne  $t0, $zero, exit2
        sll  $t1, $s1, 2
        add  $t2, $s2, $t1     # t2 = &v[j]
        lw   $t3, 0($t2)       # v[j]
        lw   $t4, 4($t2)       # v[j+1]
        slt  $t0, $t4, $t3     # v[j+1] < v[j] ?
        beq  $t0, $zero, exit2
        move $a0, $s2          # swap(v, j)
        move $a1, $s1
        jal  swap
        addi $s1, $s1, -1      # j -= 1
        j    for2tst
exit2:  addi $s0, $s0, 1       # i += 1
        j    for1tst
# ---------- restoring registers ----------
exit1:  lw   $s0, 0($sp)
        lw   $s1, 4($sp)
        lw   $s2, 8($sp)
        lw   $s3, 12($sp)
        lw   $ra, 16($sp)
        addi $sp, $sp, 20
# ---------- procedure return ----------
        jr   $ra
```

این کد در یک شبیه‌ساز تست شده است. با آرایه‌ی `9, -2, 7, 7, 0, 15, -30, 4` خروجی `-30 -2 0 4 7 7 9 15` می‌دهد.

### درون‌خطی کردن

فراخوانی `swap` و برگشت از آن چند دستور هزینه دارد: دو `move`، یک `jal` و یک `jr`. کامپایلر می‌تواند بدنه‌ی `swap` را مستقیماً داخل حلقه کپی کند. به این **درون‌خطی کردن رویه (Procedure inlining)** می‌گوییم. عیب آن: اگر رویه از جاهای زیادی صدا زده شود، کد بزرگ‌تر می‌شود و ممکن است نرخ عدم اصابت کش دستور بالا برود.

## ۴. اثر بهینه‌سازی کامپایلر و الگوریتم

کتاب برنامه‌ی مرتب‌سازی بالا را با کامپایلر gcc و سطح‌های مختلف بهینه‌سازی روی پنتیوم ۴ اجرا کرده است. نتیجه‌ی تقریبی (شکل ۲.۳۰ کتاب):

| سطح بهینه‌سازی gcc | کارایی نسبی | تعداد دستور نسبی | CPI |
|---|---|---|---|
| بدون بهینه‌سازی | 1.00 | 1.00 | 1.38 |
| سطح O1 | 2.37 | 0.33 | 1.79 |
| سطح O2 | 2.38 | 0.35 | 1.66 |
| سطح O3 (همراه درون‌خطی کردن) | 2.41 | 0.39 | 1.46 |

درس‌های مهم این جدول:

- **تعداد دستور به‌تنهایی معیار نیست:** سطح O1 کمترین تعداد دستور را دارد ولی CPI بیشتری دارد. سطح O3 دستورات بیشتری دارد ولی سریع‌تر است. این همان نکته‌ی بخش ۱ است که فقط زمان اجرا معیار قابل اعتماد است.
- **بیشترین سود در گام اول:** بهینه‌سازی سطح ۱ بیشترین اثر را دارد. یکی از کارهای مهم آن تخصیص ثبات است، یعنی نگه داشتن متغیرها در ثبات به جای حافظه.

کتاب همچنین این برنامه را با جاوا مقایسه کرده است (شکل ۲.۳۱). به‌طور خلاصه:

- **جاوای تفسیری:** حدود یک‌هشتم سرعت C بدون بهینه‌سازی را دارد.
- **جاوا با JIT:** تقریباً به سرعت C بهینه‌شده می‌رسد.
- **الگوریتم بهتر:** جایگزینی مرتب‌سازی حبابی با QuickSort برای آرایه‌ی بزرگ، سرعت را بیش از هزار برابر می‌کند. هیچ بهینه‌سازی کامپایلری چنین اثری ندارد.

نتیجه‌ی کلی: **انتخاب الگوریتم** بیشترین اثر را دارد، بعد **زبان و روش اجرا** (تفسیر یا کامپایل)، و بعد **سطح بهینه‌سازی کامپایلر**.

## ۵. آرایه در برابر اشاره‌گر

یکی از چالش‌های تازه‌کارهای C فهمیدن اشاره‌گر است. مقایسه‌ی کد اسمبلی دو نسخه‌ی یک برنامه، یکی با اندیس آرایه و یکی با اشاره‌گر، نشان می‌دهد این دو در سطح ماشین چه فرقی دارند.

```c
clear1(int array[], int size)
{
    int i;
    for (i = 0; i < size; i += 1)
        array[i] = 0;
}

clear2(int *array, int size)
{
    int *p;
    for (p = &array[0]; p < &array[size]; p = p + 1)
        *p = 0;
}
```

### نسخه‌ی آرایه

آدرس `array` در `$a0`، `size` در `$a1` و `i` در `$t0` است:

```asm
clear1: move $t0, $zero        # i = 0
loop1:  sll  $t1, $t0, 2       # t1 = i * 4
        add  $t2, $a0, $t1     # t2 = &array[i]
        sw   $zero, 0($t2)     # array[i] = 0
        addi $t0, $t0, 1       # i = i + 1
        slt  $t3, $t0, $a1     # t3 = (i < size)
        bne  $t3, $zero, loop1 # if (i < size) go to loop1
        jr   $ra
```

این کد فرض کرده `size` بزرگ‌تر از صفر است. کتاب هم همین فرض را دارد.

### نسخه‌ی اشاره‌گر

اشاره‌گر `p` در `$t0` است. در C افزودن ۱ به اشاره‌گر یعنی رفتن به عنصر بعدی، که در سطح ماشین یعنی ۴ بایت جلوتر:

```asm
clear2: move $t0, $a0          # p = &array[0]
        sll  $t1, $a1, 2       # t1 = size * 4
        add  $t2, $a0, $t1     # t2 = &array[size]
loop2:  sw   $zero, 0($t0)     # *p = 0
        addi $t0, $t0, 4       # p = p + 4
        slt  $t3, $t0, $t2     # t3 = (p < &array[size])
        bne  $t3, $zero, loop2 # if (p < &array[size]) go to loop2
        jr   $ra
```

### مقایسه

| ویژگی | نسخه‌ی آرایه | نسخه‌ی اشاره‌گر |
|---|---|---|
| تعداد دستور داخل حلقه | 6 | 4 |
| ضرب (شیفت) در هر تکرار | دارد | ندارد |
| محاسبه‌ی آدرس در هر تکرار | دارد | ندارد |
| آدرس پایان آرایه | لازم نیست | یک بار بیرون حلقه حساب می‌شود |

نسخه‌ی اشاره‌گر سریع‌تر است، چون:

- **حذف ضرب:** اشاره‌گر مستقیماً ۴ تا ۴ تا زیاد می‌شود و نیازی به `i*4` نیست.
- **حذف جمع آدرس:** آدرس عنصر خودِ اشاره‌گر است.
- **انتقال محاسبه به بیرون:** آدرس انتهای آرایه یک بار قبل از حلقه حساب می‌شود.

ولی کتاب یک نکته‌ی مهم می‌گوید: **کامپایلرهای امروزی** همین بهینه‌سازی را روی نسخه‌ی آرایه هم انجام می‌دهند. به آن **کاهش قدرت (Strength reduction)** و **حذف متغیر القایی (Induction variable elimination)** می‌گویند. پس توصیه‌ی کتاب این است که کد را با آرایه بنویسی، چون خواناتر و کم‌خطاتر است، و بهینه‌سازی را به کامپایلر بسپاری.

## ۶. تمرین‌ها

<details>
<summary>تمرین ۱: حلقه‌ی بیرونی سریع‌تر</summary>

**صورت:** در رویه‌ی `sort`، آیا می‌توان دو دستور `move $a0, $s2` و `move $a1, $s1` را حذف کرد؟

**جواب:** دستور `move $a0, $s2` را می‌توان یک بار قبل از حلقه‌ها اجرا کرد، به شرطی که `swap` مقدار `$a0` را عوض نکند. نسخه‌ی ما از `swap` آن را عوض نمی‌کند، ولی طبق قرارداد فراخوانی `$a0` حفظ‌نشده است. پس اگر `swap` بعداً عوض شود، این بهینه‌سازی برنامه را خراب می‌کند. اگر `swap` درون‌خطی شود، هر دو `move` و `jal` و `jr` حذف می‌شوند.
</details>

<details>
<summary>تمرین ۲: نسخه‌ی اشاره‌گر یک حلقه</summary>

**صورت:** حلقه‌ی جمع عناصر آرایه‌ی جلسه‌ی ۲-۵ را با اشاره‌گر بنویس. `n` در `$s0`، آدرس `A` در `$s1` و نتیجه در `$v0` باشد.

**جواب:**

```asm
        add  $v0, $zero, $zero # sum = 0
        sll  $t1, $s0, 2
        add  $t1, $s1, $t1     # end = &A[n]
        add  $t0, $s1, $zero   # p = &A[0]
Loop:   beq  $t0, $t1, Exit    # p == end ?
        lw   $t2, 0($t0)
        add  $v0, $v0, $t2     # sum += *p
        addi $t0, $t0, 4       # p++
        j    Loop
Exit:
```

داخل حلقه پنج دستور است، در مقابل هشت دستور نسخه‌ی اندیسی.
</details>

<details>
<summary>تمرین ۳: پرسش مفهومی</summary>

**صورت:** چرا نمی‌توانیم `v` و `n` را در رویه‌ی `sort` در ثبات‌های `$t` نگه داریم؟

**جواب:** چون `sort` در حلقه رویه‌ی `swap` را صدا می‌زند و طبق قرارداد، `swap` اجازه دارد هر ثبات `$t` را عوض کند. اگر `v` و `n` در `$t` بودند، باید قبل از هر فراخوانی ذخیره و بعد از آن بازیابی می‌شدند که در حلقه‌ی داخلی خیلی گران است. با گذاشتن آن‌ها در `$s`، فقط یک بار در ابتدا و انتهای `sort` ذخیره و بازیابی انجام می‌شود.
</details>
